# 系统架构

## 装配与生命周期

1. CLI 从 TOML 构造 RunConfig，从本地清单读取 DebugTask 和保留用例。benchmark 接收 Provider 和注入的 runner，创建本次运行专属日志、预算计数器和源码副本。
2. baseline.run 先用公开输入执行原始程序，保存 stdout、stderr、退出码与超时标记。公开行为正确时可以提前结束，仍须经过独立验证。
3. 直接修复路径将公开失败交给 Provider。自由调试路径允许 Provider 反复请求整数输入探针。主动路径交给 debug_controller 管理独立的 DiagnosisState。
4. 在主动路径，B 只计算假设与候选预测。A 执行选定探针，将 Observation 送回 B。达到阈值、没有正期望效用的探针（例如剩余假设对所有探针预测相同）或需保留修复预算时转入修复。探针输出超出所有预测时，B 记录异常并新增开放世界假设，A 请 Provider 重新生成假设与探针后再继续。
5. 修复循环在内存副本替换源代码，每次执行都在新的临时目录启动解释器。公开测试失败时，新的失败和累计反馈进入下一轮。预算先扣后调用。
6. C 在独立进程对冻结候选运行公开与保留用例，写出 finish。异常进入 error 事件并向调用方传播。

## 边界与生命周期约束

schemas 不依赖其余包。diagnosis 只依赖 schemas；agent 调用 diagnosis。evaluation 依赖共享类型和 A 的执行接口，runner 由 CLI 注入。保留输入只传给最终验证器。每个任务都从初始源码开始，多次运行由不同 UUID 区分。

临时目录、固定 Python 启动命令、空环境与超时适用于可信教学样例。它们没有隔离宿主机文件系统、网络、内存或子孙进程。接入未知数据集或执行真实模型生成的代码前，需要在容器或等价隔离环境限制挂载、网络、进程数、输出和内存。当前模型适配器在宿主进程运行，应视为可信组件。

单个 JSONL 可人工复盘，不提供断点续跑。恢复实现需要共同保存源码版本、剩余预算、信念、历史观察和已完成行动序号，并定义调用中断时如何记账。
